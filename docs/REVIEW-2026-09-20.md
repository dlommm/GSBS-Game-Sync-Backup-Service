# Reliability review — 2026-09-20

This bounded code review focused on save integrity, path containment, and release builds. It is not an exhaustive security audit or a guarantee of correctness.

## Fixed

- Upload conflict preconditions were checked before the store transaction, allowing concurrent clients to overwrite the same expected version. The store now checks them inside the write transaction, before deduplication and filesystem staging; the API returns 409 for the losing request.
- Distinct save slots with the same relative filename shared a physical file. New writes use slot-specific hashed filenames. Existing recorded storage paths remain readable, and shared legacy files are retained while referenced.
- Relative-path validation on Linux accepted Windows traversal and rooted paths. Validation now checks both separator conventions, and storage joins reject directory-bearing user/game IDs.
- Client write validation only checked lexical containment. It now resolves existing symlink ancestors and rejects paths outside the watch root before creating directories or backups.
- Building the Windows client left CGO disabled for a following Linux server build, producing a server without working SQLite support. Linux builds now explicitly enable CGO.
- The architecture document incorrectly said the default conflict policy bypassed the first-push guard. It now agrees with the existing client behavior.

Regression coverage includes simultaneous conditional uploads, an intervening HTTP upload, duplicate filenames across slots, shared legacy storage, cross-platform path traversal, symlink escapes, and release compiler settings.

## Remaining limitations

- Filesystem promotion and SQLite commit are separate operations. A failure between them can leave file bytes and database metadata inconsistent; this change does not provide a cross-resource transaction.
- Client symlink validation is a check before writing, not a guarantee against a local process swapping symlinks concurrently.
- Legacy strict-mode upload checks remain advisory; modern `If-Hash` and `If-Absent` checks are transactional.
- Building Windows server binaries from Linux still requires a configured Windows C compiler. Select `linux-amd64` for a native-only build.
- The `.cursor` skills, rules, and domain-agent files referenced by `AGENTS.md` and `CONTRIBUTING.md` are absent from this checkout; they could not be consulted or updated.

## Verification scope

Verification includes the Go race test suite across `server`, `pkg`, `client`, and `cmd`, native Linux server/client builds, release-script regression checks, wiki checks, and whitespace checks. The full run caught a backup test that assumed the previous filename layout; the test now verifies the exact slot-specific archive path and original save bytes, and focused backup/restore race tests pass. Native Windows/macOS execution, a browser UI walkthrough, live deployment, and a fresh dependency vulnerability scan are outside this review.
